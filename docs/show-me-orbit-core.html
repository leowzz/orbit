Core 的职责

truth → policy → view
1

入口校验

校验 topic ID = payload producer、Protobuf、32 KiB 上限、消息类型；拒绝 retained intent。

2

维护 canonical state

只保留当前 Agent/Node epoch、最新 revision、usage/codex 快照、Node 产品信息与 view revision。

3

执行策略与路由

按 TTL / future skew / 产品型号校验，并用 node_id keyed projection_routes 决定每个 Node 看哪个 Agent 数据。

4

构造 View，授权 Command

Core 是 DeviceView 的唯一构造者；把 fresh intent 解析为 OpenCodexSession command，并绑定目标 Agent。

每 1 秒： Refresh(now) → freshness 变化时重投影 stale / fresh DeviceView

什么时候才会生成 DeviceView？

四个条件必须同时成立；任一缺失，常见日志就是 observation accepted 但 views=0。

AgentState 当前epoch 匹配，source 已启用
NodeState 支持产品型号匹配 profile
Route 存在key 必须是该 node_id
Observation 有效revision 新、未过期、时间可信
AgentState + NodeState + Projection Route + Observation = DeviceView
