# 个人收件箱

Core 工作台是唯一网页入口。打开 `/box`，使用工作台密码登录，即可保存链接、文字、待办和图片。手机、电脑 App 继续使用各自的设备令牌，共享同一份收件箱。

## 配置与入口

只需要收件箱时，复制 `configs/core.inbox.example.yaml` 为 `configs/core.inbox.local.yaml`，设置工作台密码与持久化目录，然后运行：

```sh
make build-core
./dist/orbit-core -config configs/core.inbox.local.yaml
```

打开 `http://127.0.0.1:7620/box`。这个模式不需要 MQTT、Agent 或转发规则。已有数据库中存在转发规则时，Core 会拒绝切换到纯收件箱模式；已有部署应保留自己的 Core 配置、数据库和附件目录。

浏览器不需要设备令牌。原生 App 在工作台的「设备」中添加，复制连接信息或扫码连接。工作台监听器也提供 `/api/v1/`，因此二维码中的服务地址可直接使用；独立 App 监听器只提供 API，不提供网页。设备令牌不会获得工作台权限，管理会话也不能代替设备令牌。

远程访问使用 HTTPS。将整个工作台域名代理到 Core 的工作台端口即可；关闭 SSE 缓冲，不缓存 `/api/`，不记录 Authorization、Cookie 或消息正文。只公开设备 API 的域名可继续代理到独立 App 端口，但网页应使用工作台域名。

## 日常使用

- 消息按创建时间倒序显示。搜索覆盖已同步到本机的全部正文，可筛选链接、未完成、图片、已完成和已删除内容。
- 正文可以复制，链接可直接打开，不自动请求第三方预览；长消息可以展开。
- Ctrl / ⌘ + Enter 发送多行文本；图片可附带正文，也支持粘贴或拖入。图片支持 JPEG、PNG、GIF，最大 10 MB。
- 文字可转为待办，待办可以完成或撤销完成。删除影响所有设备，可在同页「已删除」中恢复。
- 主题默认跟随系统，可在工作台右上角切换；浏览器记住偏好。

## 保存与同步

网页先将草稿、图片和操作保存到 IndexedDB，再清空输入框；断网后已打开的页面仍可记录，待同步内容会明确标记。恢复连接后自动重试，沿用相同操作编号，避免响应丢失造成重复消息。版本冲突会保留修改副本，供复制后处理，不覆盖其他设备的新内容。

页面通过 SSE 接收同步水位，再读取增量内容；每分钟重连以重新验证会话，另有可见页面的定时补偿。离开收件箱页会释放连接和本地写入锁，重新进入后继续同步。同一浏览器同源只允许一个活动收件箱标签页写入，其他标签页会提示切换。

本地缓存没有另外进行内容加密。退出会清除当前工作台的浏览器缓存；仍有草稿或待同步修改时会先确认。授权失效时停止显示页面，草稿留待重新登录。暂未提供离线安装、离线重新打开网页或后台通知。图片原图按需读取，缩略图延迟加载。

## 从旧网页服务升级

服务端消息、修订号、设备登记和附件目录继续保留，无需迁库。升级时保持原 Core 的持久化配置，不删除数据卷、设备令牌或旧浏览器缓存。

1. 在旧网页中先完成同步，并处理草稿和冲突；未同步的本机内容不能跨域自动转移。
2. 更新 Core 后，将网页域名的反向代理入口指向 Core 工作台端口，并使用 Core 工作台密码登录 `/box`。旧网页密码、设备 Cookie 不会自动取得管理权限。
3. 核实消息和原图可用后再停用旧网页进程。构建与 Compose 模板已不再包含它；本地旧配置和历史镜像不会被代码修改删除。

原工作台 `/messages`、`/apps` 和 `/inbox/` 链接会进入 `/box`。旧网页独立域名的根链接需要由反向代理指向工作台并重定向到 `/box`；本次代码不更改线上域名或部署。

备份与恢复遵循 [App 运行记录](app-operations.md)：整体保留数据库与附件，恢复旧快照后重置同步 generation。设备遗失后可在工作台撤销访问，撤销不能远程擦除已经下载的数据。
