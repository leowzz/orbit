# 个人收件箱

随手保存链接、文字、待办和图片，在自己的手机、电脑和网页之间继续查看。消息按创建时间倒序排列，搜索覆盖已同步到本机的全部内容；可筛选链接、未完成待办、图片和已完成待办。

## 最少配置

只需要消息时，使用 `configs/core.inbox.example.yaml`。设置管理密码和持久化目录后运行 Core：

```sh
make build-core
./dist/orbit-core -config configs/core.inbox.local.yaml
```

先将示例复制到上面的本机配置路径。这个模式不需要 MQTT、Agent、Node ID 或转发规则；不要直接覆盖已有的 MQTT 部署配置。已有数据库中存在转发规则时，Core 会拒绝切换到纯收件箱模式，以免静默停用设备。

1. 打开管理台（默认 `http://127.0.0.1:7620`），在「App 与收件箱」为每台手机、电脑或网页添加一个设备。
2. 点击「复制连接信息」，在 App 中粘贴；Android 也可扫码。App 会先验证地址和授权，再保存连接。
3. 网页打开同一服务的 `/inbox/`，粘贴这台网页设备的连接信息即可。设备令牌不会获得管理台权限。

管理台监听器同时提供 `/inbox/` 和 `/api/v1/`，因此二维码中的服务地址可直接使用。原有独立 App 监听器仍然可用，打开其根地址会进入收件箱。远程访问必须部署 HTTPS；App 发布版不接受明文 HTTP。

部署在同一个 HTTPS 域名时，可将所有流量代理到管理台端口（管理台自身仍需密码），也可以只公开个人消息路径并将管理功能限制在内网：

```caddyfile
orbit.example.com {
    @personal path /inbox /inbox/* /api/v1/*
    handle @personal {
        reverse_proxy 127.0.0.1:7622 {
            flush_interval -1
        }
    }
    # 管理台应通过单独的内网/身份验证入口访问。
    handle {
        respond 404
    }
}
```

若管理台与 App 公网域名不同，连接信息中的地址需要改成实际 App 域名；不要把管理密码作为设备令牌。关闭代理对 SSE 的缓冲，不记录 Authorization、Cookie 或消息正文。

## 日常使用

- 一次点击复制正文；链接提供安全的外部打开入口，不自动请求链接预览。
- App 和网页可输入多行文本，支持 Ctrl / ⌘ + Enter 发送；图片可附带正文，网页还支持粘贴和拖入图片。当前不支持任意文件、视频或飞书卡片导入。图片支持 JPEG、PNG、GIF，最大 10 MB。
- 长消息可以展开阅读。App 上滑时收起输入区，下滑或切换筛选时恢复。
- 待办可完成或撤销完成；普通文字可转成待办。
- 删除前会说明跨设备影响；已删除内容可在管理台恢复。
- App 的「状态与组件」使用当前 HTTPS 连接读取状态摘要。Android 桌面组件是可选入口，继续沿用已有 MQTT 后台同步；只有使用这项功能才需要配置它。

## 保存与同步

App 先将内容写入本机持久队列，然后清空输入框；离线新消息立即显示「待同步」。网页采用 IndexedDB 保存草稿、图片和待同步操作，在已打开页面断网时仍可继续记录。网页离线时重新打开页面不保证可用，暂未提供离线安装或后台通知。

服务端确认后才显示已同步。重试使用同一操作编号，响应丢失不会重复创建消息。版本冲突保留修改供复制处理，不覆盖另一台设备的新内容。网页的同一设备只允许一个活动标签页写入本机缓存，避免两个标签页互相覆盖草稿；其他标签页会提示切换。

原图和缩略图按需读取，不会主动将个人链接或图片发送给第三方。数据保存在自己部署的 Core 和当前设备缓存中，缓存没有另外进行内容加密。网页退出会清除此浏览器的该设备缓存，仍有草稿或待同步操作时先确认；撤销授权不会远程擦除已经下载的内容。

## 已有 Web Node

现有 Web Node 首页增加「收件箱」入口。在 `web` 下增加一次服务端连接：

```yaml
web:
  listen: 127.0.0.1:8080
  auth:
    password: <Web Node 访问密码>
  inbox:
    url: https://orbit.example.com
    token_file: secrets/web-inbox-token
```

令牌文件保存为 Web Node 单独创建的设备令牌，限制为运行服务的用户可读。浏览器继续使用 Web Node 自己的访问密码；上游令牌保留在服务端，不写入网页、URL 或日志。

保留原有 `mqtt` 和 `node.id` 时，状态页和消息页同时可用；移除它们后进入纯网页收件箱模式，首页直接显示消息，不连接 MQTT。完整示例见 `configs/web.inbox.example.yaml`。最简单的部署仍是直接使用 Core 内置网页，不启动单独 Web Node。

## 授权与备份

App 令牌保存在系统安全存储。Core 网页用 HttpOnly、SameSite=Strict Cookie 保存设备凭据；远程 Cookie 要求 HTTPS。Cookie 请求检查来源，设备访问与管理权限分离。每台设备独立授权，遗失后在管理台撤销，服务端下一次请求即拒绝访问。

纯收件箱模式也提供管理台和设备登记。启用 MQTT 后才能添加状态转发规则；状态摘要不是使用消息的前提。

备份和恢复继续遵循 [App 运行说明](app-operations.md)，整体备份数据库与附件，恢复旧快照后重置同步 generation。此改动没有新增数据库 schema，也不修改既有消息内容。
